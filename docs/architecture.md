# 实现与集成说明

本项目是独立扩展，基于 Dada 0.12.2 适配任务界面。窗口控制与日程组件分层，便于原作者评估或抽取桌面能力。

## 窗口与停靠

`DesktopWindowController` 通过 Obsidian 的 popout leaf 创建宿主窗口，再从 Electron remote 获取对应 BrowserWindow。窗口解除父子关联，重复打开只唤回现有窗口；默认大小 900×700，按工作区裁切，默认不置顶。

标题栏使用系统原生 `app-region: drag`，覆盖 Blue Topaz 的合并 view header；交互按钮设为 `no-drag`。窗口移动/缩放事件触发停靠计算，拖动完成时重新判断。只在停靠且自动隐藏开启时，以 100ms 间隔检查光标，不定时扫描工作区标签。

`dock.js` 提供工作区边界计算与纯状态机。左侧间距为 `window.x - area.x`，右侧间距为 `area.right - window.right`，负数表示越界，仍需吸附。早期只比较绝对距离，导致越过边缘超过 16px 后不再匹配；1.0.5 已改用有方向的距离。

展开窗口在鼠标离开且无编辑/菜单操作后等待约 600ms，再隐藏内容窗口，显示 10×120 的独立边缘窄条。光标在窄条内约 150ms 后展开。屏幕坐标使用 Electron 逻辑像素；允许小幅窗口边框舍入误差，避免循环调整位置。

## 界面与数据

轻量入口与完整 UI 分开构建。`ui.cjs`、`ui.css` 在需要时读取，在最终窗口文档中挂载一次；弹窗、菜单、事件使用触发操作所属的窗口。样式、字体与动画限定在扩展作用域。

适配器读取已启用 Dada 的设置，调用同一套格式的 Markdown 任务读写。界面副本来自上游，后续格式变化需要同步。普通 body 焦点类变化不重读任务；明暗主题变化仅更新配色，重叠任务读取合并。

## 启动与生命周期

恢复小窗在宿主启动打开行为完成后延迟执行。Homepage 会替换该行为，因此当前实现包装 `app.runOpeningBehavior`；启用时若已存在窗口或创建请求，不再重复展开。

专用窗口将普通笔记打开请求在创建编辑器之前路由到主窗口，不跨文档搬动已初始化的编辑器。实现包装了 workspace 获取 leaf 和专用 leaf 的 `setViewState`，清理时恢复自身包装。该部分使用宿主内部结构，升级 Obsidian 后需要回归。

退出、停用扩展或停用 Dada 时，清理界面、事件、定时器、内容窗口及边缘窄条。窗口状态使用临时文件写入后重命名保存；主动关闭与退出恢复分别处理。

## 合入上游时的建议

- 优先复用窗口控制器、停靠计算及状态机，直接挂载本体任务组件，减少 UI 副本维护。
- 通过明确的宿主接口提供打开任务视图、配置读写及生命周期，评估能否减少工作区方法包装。
- 检查 Electron remote 和工作区内部 API 的可替代方式，并补充真实多屏与 DPI 混合场景。
- 个人版本的一次性自动隐藏迁移应由正式产品的默认设置或安装引导接管。

当前代码用于交流与参考，不承诺可直接合并上游。
